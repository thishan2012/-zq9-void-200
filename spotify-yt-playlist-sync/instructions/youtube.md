# YouTube setup

1. In Google Cloud Console, create/select a project and enable **YouTube Data API v3**.
2. Create an API key. Restrict it to YouTube Data API v3. Avoid IP restrictions unless they allow GitHub-hosted runner IPs (these change). Monitor your quota in Google Cloud.
3. In GitHub repo → Settings → Secrets and variables → Actions → New repository secret, create `YOUTUBE_API_KEY` with that key. Never paste the key in an issue, log, or chat.
4. The YouTube playlist URL is already set in `YOUTUBE_PLAYLIST` in `.github/workflows/sync.yml`. To use another playlist, edit the URL there. For a local run, set the `YOUTUBE_PLAYLIST` environment variable instead.

This uses the official `playlistItems.list` and `videos.list` endpoints rather than yt-dlp. Public and accessible unlisted playlists can be read using an API key; playlist access and API quota must allow all pages and video details to be read. Video details are requested in batches of up to 50.

Normal music-video uploads work as well as Topic channels: the sync looks for `Artist - Song` in the title, a Topic-channel credit, or an explicit artist credit in the video description (for example `Artist: Name`, `Name - Song`, or autogenerated `Song · Artist 1 · Artist 2` credits when the song title matches). Explicit description credits take precedence over the channel name. Generic channels such as `Release - Topic` are not assumed to be artists; without other credits the title-based fallback is used.

There are three matching methods, tried in order:
1. **Strict:** search with artist and title, and require an exact normalized title plus primary artist. Version information is retained.
2. **Loose fallback:** if the first method finds no match, search Spotify using the full YouTube video title (with presentation-only labels removed). Choose the closest sufficiently similar title; the artist is not required to match. YouTube/Spotify titles must have matching recognized version markers, including `Slowed`, `Ultra Slowed`, `Super Slowed`, `Sped Up`, `Extended` and `Reverb`. Named remixes/edits require the full normalized title to match. Close ties are skipped rather than chosen arbitrarily. The Actions log labels these matches `LOOSE MATCH` so they can be reviewed.
3. **Detail fallback:** if both methods miss, search again using core song-title words, then compare title words (including possible word-order changes) and recognized version markers. A matching artist helps, but is not required; without one the title must match more closely. When both services provide a duration, candidates with a substantially different duration are rejected, allowing some room for video intros/outros. The log labels matches `DETAIL MATCH`. This method may still skip songs if metadata, versions or results are ambiguous.

## Manually selected tracks

`data/track-overrides.json` maps a YouTube video ID to a Spotify track ID, both taken from their links. These are explicit user choices, used before automatic matching and logged as `MANUAL MATCH`. The supplied PARAISO mapping is included. Confirm the recording and version yourself: an override bypasses automatic title, version and duration checks. Duplicate checks and pending-write safeguards still apply, and unavailable videos are skipped. Malformed mappings stop the run; if the file is absent, automatic matching runs as usual. Existing entries in the state database are not automatically re-evaluated when an override changes.

**Fallback matching can select the wrong song or artist**, especially when a video has no reliable artist credit. None of the three methods uses audio fingerprinting or guarantees the same recording, and not every possible version label is recognized. Review `MANUAL MATCH`, `STRICT MATCH`, `LOOSE MATCH`, `DETAIL MATCH` and `SKIP` lines in a dry run before syncing. Private/deleted videos, absent versions and ambiguous results are skipped. The sync never removes existing Spotify entries or automatically re-evaluates videos already stored in `data/sync-state.json`.
